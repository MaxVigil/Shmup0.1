# Shmup routing rule

Before planning or editing, run `npm run context:validate` from the current checkout. Then read that checkout's `AGENTS.md` completely and follow its repository identity, source hierarchy, work authorization, skill routing, verification, and handoff rules.

Canonical requirements live only in the current canonical checkout's `Project Documentation/` directory. Do not jump to another absolute path or similarly named repository.

Do not create a `memory-bank/` or copy requirements into `.clinerules/`. If a rule or skill conflicts with canonical documentation, canonical documentation wins and the affected work stops for clarification when the conflict changes product behaviour.
